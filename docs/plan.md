# План: настройки со сгруппированным меню, плавающей кнопкой «Сохранить» и предупреждением о несохранённых изменениях

## Текущее состояние (что находим)

- `/settings` (`src/routes/settings.tsx`) — автосохранение на каждый клик/keystroke через
  `s.set(...)`; кнопка «Сохранить настройки» (`SaveCheck`, SettingsExtras.tsx:363) иллюзорная —
  только перечитывает хранилище и пишет «Всё сохранено ✓».
- Настройки раскиданы:
  - **«Защита серии»** (`plan.settings`: bonusMax, bonusRestoreDays, freezeMax, freezeThresholdPct,
    автосейв на каждый keystroke) — `src/routes/plans.tsx:112–174`;
  - «Отпуск» — диалог из шапки (`VacationButton.tsx`, action скорее, чем настройка);
  - mute-кнопка в плеере (`play.$workoutId.tsx:206–216`) — контекстный переключатель на время
    тренировки, не конфигурация.
- Плавающих кнопок в коде нет; shadcn `alert-dialog`, `dialog` уже используются.

## Что делаем

### 1. Перенос разбросанных настроек в меню настроек

- «Защита серии» целиком переезжает на `/settings`; на `/plans` в блоке «Защита серии» остаётся
  **только строка статуса** (доп-выходные / заморозки — уже есть `ProtectionBar`) без полей ввода.
  Значимую механику x/n/y править можно будет только здесь.
- Отпуск: в настройках появляется строка «Режим отпуска» с кнопкой, открывающей тот же диалог
  (`VacationButton` самодостаточен — переиспользуем как есть). Быстрый доступ в шапке **остаётся**
  (иначе непонятно, что серия заморожена).
- Mute в плеере не трогаем: это переключатель на время тренировки (как пауза), дублирует
  `voice.enabled` из настроек.

### 2. Черновик → «Сохранить» (вместо автосейва)

- Захватываем снапшот настроек при входе на `/settings` в локальное состояние (draft):
  `name, reminders, photoReminder, voice, ai, ffmpegKey, ffmpegOptions, ffmpegOut, plan.settings`.
- Все контролы редактируют только draft (`update(partial)`-функции). Store не трогается до нажатия
  «Сохранить» (или подтверждения выхода с сохранением).
- «Данные» (экспорт/импорт/сброс) — действия, не редактор: срабатывают сразу и не являются частью
  черновика.

### 3. Плавающая кнопка «Сохранить»

- Fixed-кнопка внизу экрана (`z-40`, выше контента и glass-подложки), контейнер в ширину контента
  (`max-w-xl`), учёт `env(safe-area-inset-bottom)`.
- **Всегда видна на `/settings`** (не исчезает по требованию): когда изменений нет — `disabled`,
  подпись «Сохранено»; когда есть — активная «Сохранить изменения» с внутренним счётчиком
  изменённых полей? — нет, просто активная кнопка.
- `pb` нижнего паддинга контента на `/settings` увеличиваем, чтобы кнопка не накрывала последний
  блок («Данные»). Кнопка не должна гасить события — pointer-events только на самой кнопке.

### 4. Предупреждение при выходе с несохранёнными изменениями

- dirty = глубокое сравнение draft vs текущий store (или at-entry снапшот).
- Перехват выхода из `/settings`:
  - TanStack Router `useBlocker` (v1.170 поддерживает) — ловит и ссылки, и кнопку «Назад», и смену
   History API.
  - fallback, если blocker в этой версии капризен: свой контекст на корне, кнопкам навигации
    (`BottomNav`, header-линки) — но blocker предпочтительнее.
- Диалог (`AlertDialog`, пользовательские формулировки): заголовок
  «Сохранить изменения в настройках?», текст «Ты менял(а) настройки, но не сохранил(а) их», кнопки:
  - **«Сохранить»** — писать draft в store, затем переход;
  - **«Удалить изменения»** — откатить draft, затем переход;
  - **«Остаться»** — отмена навигации.
- `beforeunload` — не добавляем (PWA, дублирует blocker, редко полезен). Окно можно закрыть — чирн
  черновик не критичен, мы не пишем half-state в store.

### 5. Группировка меню настроек (итоговый порядок)

1. **Профиль** — имя (+ «Режим отпуска» здесь же, как режим, а не параметр).
2. **План и серия** — перенесённая «Защита серии» (4 числовых поля + пояснение).
3. **Уведомления** — «О тренировках» (вкл., час) и «О фото прогресса» (вкл., интервал, час,
   статус последнего фото) в одной карточке, как подсекции; кнопка разрешения уведомлений общая
   внизу карточки.
4. **Звук и голос** — как сейчас (VoiceSection → на draft).
5. **ИИ-помощник** — провайдер, ключи, base URL, модель, проверка.
6. **Видео** — ключ ffmpeg, пресеты, advanced, проверка.
7. **Данные** — экспорт/импорт 6 секций, сброс всего (действия, вне черновика).

Заголовок раздела + жирный текст, между карточками `space-y-4`; ничего не прячем в аккордеон,
страница и так умещается.

## Риски

- `useBlocker` в TanStack Router v1.170: поддерживается, но API менялся — если с behavior
  отметится проблема, fallback: свой компонент в корне с pushState-перехватом (последний
  рубеж, надеюсь не понадобится).
- Локальный «числовой» input при переходе на управляемый draft может терять каретку при
  пустом значении — тест вручную (классическая ловушка: держим строковое значение в драфте,
  нормализуем при commit).
- «Данные» вне драфта: экспорт/импорт не нужно блокировать, но «Сбросить всё» — разрушительное
  действие, оставим `confirm` (уже есть) — вне задачи.
